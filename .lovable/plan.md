
# MVP alpha-ship plan

Four workstreams. Each is demoable in isolation.

---

## 1. Cross-tenant security audit + automated test

**Audit (read + fix-as-found):**
- Every table already has `auth.uid() = user_id` RLS — verify each policy is scoped (not `true`) and that no server fn trusts a client-supplied `user_id`.
- Every `createServerFn` in `src/lib/**` that touches a user-owned table uses `requireSupabaseAuth`. The only legitimate `supabaseAdmin` reads (e.g. cross-tenant lookup in `search.functions.ts` for the `gio` flag) must filter results to `context.userId` before returning anything user-visible.
- Re-check `candidates-panel`, `outreach-panel`, `app.c.$id` for any direct `supabase.from(...)` reads/writes — they're RLS-backed but double-check no `.eq("user_id", clientValue)`.

Anything ambiguous gets called out in the closing message.

**Automated test (`src/lib/__tests__/tenant-isolation.test.ts`, runs via `bunx vitest run`):**
- Uses `supabaseAdmin` to create two throwaway auth users (A, B).
- Seeds: 1 conversation, 1 candidate, 1 sourcing_project, 1 outreach_draft per user.
- Signs in as A via `signInWithPassword`. Asserts:
  - `select * from candidates` returns only A's rows
  - update/delete on B's rows returns 0 rows affected
  - Server fns called with B's IDs throw or return empty
- Tears users down. Documented in `README` so CI/devs can re-run.

## 3. Free cap: 3 sourcing projects × 5 real results + 15 blurred placeholders

**Concept (corrected):** the 15 blurred rows are not "fake data we pass off as real." They're a *visual placeholder for results Apollo would happily return* — we just haven't paid the credits to fetch them yet. The card is blurred, name/title scrambled (`██████ ████`, geometric avatar), with a clear lock pill: **"Locked — unlock with credits"**. Click → upgrade modal. Once they buy credits, the next search (or "Source more") returns 20 real rows and there's nothing fake to replace.

So this becomes much simpler — no Lovable AI fake generator, no risk of misrepresentation.

**Schema (one migration):**
- `profiles`: add `plan text default 'free'`, `credits_remaining int default 0`, `sourcing_projects_used int default 0`.
- `sourcing_preview_candidates`: add `is_locked boolean default false` (placeholder row, not enrichable until credits unlock).
- `credit_ledger` table: `(user_id, delta int, reason text, stripe_session_id text, created_at)` — auditability.

**Server changes:**
- `createSourcingProject`: if free plan and `sourcing_projects_used >= 3`, throw typed error `FREE_PROJECT_LIMIT`. Increment counter on success.
- `runSourcingSearch`: read profile → compute `realQuota = plan === 'free' ? 5 : 25`. Pass `maxResults = realQuota` down through `searchApollo` + `searchPdl` (cap their internal page loop). After insert of N real rows, insert `(20 - N)` rows with `is_locked: true`, empty preview JSON, no `external_id`. They sort to the bottom by `keyword_score = 0`.
- `collectCandidates`: refuse to collect locked rows (typed error → UI shows upgrade modal).
- "Source more" (`source-more.functions.ts`): also gated on credits — on free plan it does nothing and prompts upgrade. On paid, replaces locked rows with fresh Apollo results.

**UI (`candidates-panel.tsx` + preview list/grid):**
- Locked rows: `<div class="blur-sm select-none pointer-events-none">` over the same card markup, with skeleton text in the preview JSON so it has shape. Overlay = small lock icon + "Unlock" pill.
- Clicking anywhere on a locked row → upgrade modal.
- Top of panel: "5 of 20 results shown · unlock 15 more" with CTA.

**Front-end guards elsewhere:**
- "New project" button → tooltip + upgrade modal when at the 3-project free cap.
- Chat agent's `start_sourcing` tool surfaces the same friendly error so the chat narrates it ("You've used your 3 free sourcing projects. Upgrade to keep going.").

## 4. Stripe credit packs (seamless Lovable Payments)

- Run `payments--recommend_payment_provider` → expect Stripe for digital SaaS.
- Enable with `payments--enable_stripe_payments`.
- Tax handling: **option 2 (calculation only, +0.5%)** — global SaaS, you handle remittance.
- Three packs via `batch_create_product`:
  - **Starter** — 25 candidate credits + 5 projects — $29
  - **Growth** — 100 credits + 25 projects — $99 *(Most popular)*
  - **Pro** — 500 credits + unlimited projects — $399
- `src/routes/_authenticated/billing.tsx` — 3-card pricing, "Current plan: Free — N projects left, M credits", purchase history from `credit_ledger`.
- `src/routes/api/public/stripe-webhook.ts` — verifies signature, on `checkout.session.completed` reads `metadata.pack`, increments `credits_remaining`, expands project quota, writes `credit_ledger`.
- `src/lib/billing.functions.ts` — `createCheckoutSession({ pack })` server fn returns Stripe URL.
- `src/components/billing/upgrade-modal.tsx` — reused everywhere we hit a cap.
